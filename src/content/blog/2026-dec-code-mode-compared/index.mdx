pi, Claude Code and OpenCode ship code mode, and Cloudflare and Anthropic offer the parts to build one. All five agree on the idea: the model writes one program, a sandbox runs it, and only the result goes back. They differ on where the program runs, what can stop it, where the permission check sits, and how the model finds its tools. The earlier posts cover [the concept, Cloudflare and Anthropic](/blog/code-mode-explained/), [pi](/blog/code-mode-pi/), [Claude Code](/blog/code-mode-claude-code/) and [OpenCode](/blog/code-mode-opencode/) one at a time.

## Isolation

The five walls sit at different distances from the host.

- **Claude API**: the farthest. The Python runs in Anthropic's container with no internet, and each tool call pauses the code until your application answers.
- **Cloudflare**: a new V8 isolate per run, loaded with no network. Tool calls cross to a `ToolDispatcher` on the host over Workers RPC, and credentials stay there.
- **pi**: a new QuickJS VM, compiled to WebAssembly, on its own worker thread. Its only imports are a WASI shim and one host-call entry point. The heap stops at 256 MiB.
- **Claude Code**: a `vm` context inside the Claude Code process, with no `import`, `require` or `process`, and with `eval` and WebAssembly turned off. The sandbox setting covers the shell commands a script runs; the JavaScript and its file, web and MCP calls run in the CLI process.
- **OpenCode**: the closest. Its own bytecode VM, written in TypeScript, runs in the OpenCode process. It is safe because it implements no file system, process or module, not because a runtime walls it off. It has no memory cap, and its `fetch` reaches the network.

## Who can stop a runaway program

A `while (true) {}` never yields, so a timer in the same event loop never fires. The stop must come from something the loop cannot block. Claude Code builds it into the program: the transpiler adds a step counter, and my test script stopped 0.3 seconds after the call with this error:

```text
RangeError: REPL: a turn ran 300000000 steps, its budget (a step is one pass through a loop
or one call of a function), and was stopped.
```

pi runs the program on a worker thread, so the main thread can stop it, but only when the script set `timeout_ms` or the user cancels. OpenCode's VM yields to the Effect scheduler between slices, so a cancel interrupts it; without one, the loop ran 300 seconds at full CPU. Cloudflare's executor races a `setTimeout` inside the isolate, which the loop blocks, so only the platform's CPU limit stops it in production.

## Where permission checks fire

Claude Code checks twice. A hook or `ask` rule on `REPL` and the auto mode classifier see the whole script before it runs. Then every call inside it goes through the rules and hooks under the tool's own name: a deny rule on `Bash(touch *)` refused one command and the script went on.

OpenCode checks each call: the action `<server>_<tool>` for MCP tools, and `webfetch` with the URL for `fetch`. Its default policy allows every action except reading `.env` files, so nothing prompts. pi sends each nested call through the same `tool_call` hooks as a direct call, but has no approval step of its own; the check exists only when an extension adds one.

Cloudflare decides before the run: `createCodeTool` leaves tools marked `needsApproval` out of the sandbox, and the connector runtime pauses on `requiresApproval`. The Claude API leaves the check to you, because your application runs every call.

## Tool discovery

- **The full typed API in the prompt.** Cloudflare's `codeMcpServer` renders every tool as TypeScript. For the same 46 GitHub tools that is 18,362 tokens, more than the 11,132 of the JSON definitions, and any schema change breaks the prompt cache.
- **A search step.** pi lists no MCP tools, only one system prompt line per server; scripts find them with `searchTools()` and `describeTool()`, as in Claude Code. Cloudflare's `openApiMcpServer` has `search` and `execute` at 1,264 tokens for any size of API. The cost is one more step before the real call.
- **A budgeted catalog.** OpenCode lists namespaces with tool counts, then signatures up to about 2,000 tokens. For GitHub that was the first 3 of 46 in alphabetical order; the rest need `search()`. The catalog saves a step only when the right tools fit in the budget.

## Other agents

Codex CLI 0.171.0 has code mode behind the `code_mode` feature, at the stage the source calls "under development", off by default. The model sends raw JavaScript to an `exec` tool, which runs it in V8 in a separate code-mode host process. A script that runs past 10 seconds returns a cell ID and continues through `wait`, and output stops at 10,000 tokens per call by default.

Goose 1.60.2 has a **Code Mode** platform extension, off by default. The model finds tools with `list_functions` and calls them with `tools.call("extension__tool", args)`. The JavaScript runs on Boa, an interpreter written in Rust, inside the Goose process, with a budget of 2,000,000 instructions and 100,000 loop iterations.

Gemini CLI 0.70.0 and Cline 4.1.26 have no tool that runs model-written code against the agent's other tools.

## Which one to use when

- **You use Claude Code.** Turn Code Mode on for chains of dependent calls: in part 3 it cut a ten-call chain from 12 requests to 3. Of the three agents, it is the only one with a default limit on a runaway script, and it checks both the script and each call. It needs the interactive terminal and a direct login, and it saves little on MCP definitions, which Claude Code already defers.
- **You build your own agent or MCP server.** Use Cloudflare's executor. Of the designs you run yourself, the V8 isolate with no network is the strongest wall. For a large API, use `search` and `execute`, not the full typed API.
- **You build on the Claude API and Python is fine.** Use programmatic tool calling. Anthropic hosts the sandbox and your code sees every call; MCP connector tools are out.
- **You pick an open-source agent for MCP-heavy work.** Use pi. Its request grew by 50 tokens for 46 tools, its VM runs on a thread that a cancel or `timeout_ms` can stop, and nested calls fire the same hooks as direct ones. Add a `tool_call` hook if you want approvals. OpenCode is the close second: on by default and the fastest sandbox, but add a `webfetch` deny or ask rule, because its programs reach the network and only a cancel stops a loop.
